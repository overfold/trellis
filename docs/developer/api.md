# Internal APIs and transport

This page describes node-to-node implementation contracts. Operator tools and external integrations use the [public HTTP API and Go client](../public/api.md), not these endpoints. Wire types live in `internal/nodeapi`, node and agent clients in `internal/client`, and shared HTTP transport in `internal/transport`. Public wire types and clients remain in `api` and `client` without server-side dependencies.

## Node identity and enrollment

`tlsutil.GenerateNodeCert` accepts only CA material and the node UUID, with no
caller-supplied SAN argument. Node identities cannot claim arbitrary DNS names.

`POST /v1/nodes`, `POST /v1/nodes/{id}/heartbeat`, `GET /v1/internal/discovery`, `POST /v1/raft/join`, and the agent API on port 8127 require a trusted node certificate whose URI SAN identifies the immutable node UUID. Every identity certificate also has the DNS SAN `<uuid>.node.trellis`; node-to-node clients verify that specific identity. Registration and heartbeat IDs must match the caller's UUID.

Each UUID is durably bound to its admitted certificate and role. Removed UUIDs have replicated tombstones and are rejected on node-authenticated paths, enrollment, and Raft join regardless of their certificate. Raft join is available only to control-plane identities, derives the member ID from the certificate, and admits a non-voter. In managed mode its response carries the member IDs and CA private key; workers never call this endpoint. Outbound Raft streams resolve the target address through membership and verify that exact UUID's certificate; inbound streams require a bound, non-removed control-plane member identity.

Inbound TLS Raft streams reauthorize every MessagePack RPC frame against local replicated trust before releasing it to NetworkTransport, including its heartbeat fast path. The header UUID must match the verified certificate UUID, its address must match that member's configured address, and legacy leader/candidate address fields cannot disagree with the header address. A joining replica with no configuration yet relies on its bootstrap-trusted certificate identities until the first configuration arrives. Checks are frame-boundary checks, not socket-read checks: buffering/pipelining cannot admit later RPCs under an earlier authorization decision. Snapshot bytes stream after the admitted snapshot header without aggregate buffering. A rejected frame closes the stream. Revocation on a replica takes effect once that replica applies the tombstone; a disconnected replica cannot know a removal until replication catches up. An already-admitted RPC/snapshot is not cancelled midway. Keep the tombstone-before-membership-change ordering and join-member bootstrap trust to preserve recovery and partition safety.

Managed-only `POST /v1/nodes/enroll` uses a role-bound join token over TLS authenticated with the pinned node CA. Enrollment takes `role` and a PEM `csr`, ignores requested names, and returns an identity certificate; the private key stays on the enrolling node. Only control-plane nodes join Raft and receive the CA key. `POST /v1/nodes/api-certificate` signs a CSR for the shared `trellis` API name only for a bound, non-removed current control-plane member. Its certificate is valid for 24 hours and renewed hourly; workers can never obtain that name. A worker's port 8128 relays TCP to a control-plane endpoint, preserving client-to-API TLS and client identity end to end. `GET /v1/internal/control-plane` and registration/heartbeat responses provide relay targets and the elected leader UUID; workers cache this public topology, not replicated state. `GET /v1/internal/node-role` reports the authenticated node's durable role for administrator-authorized promotion checks.

## Registration, heartbeats, and discovery

Registration validates the agent endpoint before any state mutation: `host` must be a nonempty ASCII DNS hostname (labels of 1–63 alphanumeric/hyphen characters, no leading/trailing hyphen, at most 253 characters excluding an optional trailing dot) or an IPv4/unbracketed IPv6 literal, including scoped IPv6. Dotted numeric strings must be valid IPv4 literals. URLs, embedded ports, bracketed IPv6, whitespace, and empty labels are rejected. `port` must be 1–65535 inclusive. Invalid registration returns `400` and leaves existing node state unchanged; identity mismatch still returns `403`. Validation does not resolve DNS or test reachability.

Heartbeat authorization first requires the path UUID to match the authenticated node certificate (`403` otherwise, including for administrator credentials without a node identity). A nonzero body `id` must then match that path UUID; a mismatch or malformed body ID returns `400` without recording liveness, observations, or Raft progress. For compatibility, an omitted, null, or zero UUID body ID is unspecified: the authenticated path UUID remains authoritative. A malformed path UUID returns `400`.

The authenticated control-plane topology response also includes `wireguard_port_count`. Workers fetch it before initializing local networking: an omitted local count adopts the cluster value, while an explicitly different count is rejected.

WireGuard registration keys must be canonical base64 encodings of 32-byte
X25519 public keys and must not be low-order points that cannot authenticate a
peer. Invalid keys return `400` before persistence or peer-plan propagation.
The daemon derives its identity from local private material and durably
publishes the matching public file before registration; a missing public file
is recoverable without private rotation, but corrupt or inconsistent state
stops startup. See [operator repair](../public/operations.md#wireguard-identity-recovery).
Registration cannot prove possession of the advertised private key; the
authenticated node remains responsible for its local key pair.

Registration reports physical and allocatable resources, workload eligibility (`runs_workloads`, default true), capabilities, and the node's WireGuard public key, advertised endpoint, local port base, and range size. Heartbeats carry a complete current observation, including capabilities and `raft_applied_index`; optional host usage and task log usage fields may be absent when counters are unavailable or the runtime cannot measure its log directory. They return no desired state. A `200` with topology JSON means the leader validated the report and recorded liveness, not that allocation observations have been durably persisted: observations are queued asynchronously. An unregistered node's heartbeat fails, causing registration before the next heartbeat.

Heartbeat bodies are limited to 32 MiB and 320,000 allocation-task reports (`413` on excess). A task `reason` is allowed only for phase `failed`, and currently only `restart_budget_exhausted` is accepted. A task in phase `starting` may carry `start_failure`: `attempt`, a message of at most 1024 bytes, and optional code `stale_generation`, `execution_conflict`, or `restart_budget_exhausted`. Other phases reject that field. The leader counts a failure for the allocation's current attempt once; a non-retryable code immediately fails it.

The node client bounds each registration, heartbeat, and discovery HTTP request to ten seconds, including connection establishment and response-body consumption. A stalled body is closed and its request cancelled when the budget expires. Caller cancellation terminates the request sooner during shutdown. Failed heartbeats retain the registration-before-next-heartbeat retry path; each new HTTP request receives a fresh budget.

Internal discovery exposes catalog entries only for namespaces with active allocations on the authenticated node. The node resolver additionally checks the workload's source namespace before answering. The leader combines durable namespace port slots with node-advertised bases to build WireGuard peer plans; see [networking](node-internals.md#networking).

`GET /v1/internal/discovery` accepts `job` and `label` filters. As with public allocation listings, `label=key` requires presence and `label=key:value` requires presence plus an exact value match; `label=key:` matches a present empty value, not an absent label. The first colon separates the key from the value.

## Durable node execution intent

Nodes pull `GET /v1/nodes/{id}/execution?epoch=E&version=N` from the current leader on port 8128, using zeroes before the first accepted document. The path UUID must exactly match the authenticated node certificate. The client requires verified mTLS, sets TLS `ServerName` to `<leader-uuid>.node.trellis`, and also checks the peer certificate's node URI identity against the expected leader UUID obtained from trusted topology. It refuses redirects and rejects a fetch if the trusted leader ID or address changes during it. The shared operator identity `trellis` is not sufficient for execution authority.

The response is a complete `ExecutionIntent` projected from committed authority: `node_id`, `leader_id`, positive `epoch` and `version`, `complete`, `cleanup_absent`, `allocations`, and `network_plans`. Documents are cached only in leader memory, never written to Raft. Version advances when projected content changes within an epoch, including retry eligibility and recovery-grace changes; a new durable control epoch permits rebuilding with version 1. Agents compare `(epoch, version)` lexicographically and reject different content at the same pair. A current epoch/version long-polls for up to 25 seconds, then returns the same complete document; the client budget is 35 seconds. An older epoch returns the current document immediately. Missing authority returns `503`, never an empty cleanup-authorizing view. Responses are `Cache-Control: no-store`, although the agent explicitly persists accepted intent locally for recovery.

Allocation modes are `run` (RUN: authorize admission of this generation/attempt), `retain` (RETAIN: preserve established execution without admitting a start), and `cleanup` (CLEANUP: generation-fenced resource teardown, with `retain_logs` controlling history). Requests carry generation, revision, execution hash, attempt, epoch, and sequenced drain state. The agent rejects incomplete, stale, conflicting-version, mixed-identity, or invalid documents before persistence or cleanup. `complete` alone does not authorize omission-based deletion: `cleanup_absent` must also be true. During the leader's 30-second recovery grace it is false; explicit CLEANUP entries still apply. Fetch failure is never proof of absence.

`GET /v1/nodes/{id}/execution/{allocation}/credentials?version=N&generation=G&epoch=E&attempt=A` separately returns delivered secret bytes and task-scoped environment overrides for a currently authorized RUN attempt. It uses the same exact node/leader mTLS identity checks and a ten-second client budget. The leader validates the current projected epoch/version, generation, and attempt before resolving credentials and revalidates authority before delivery (`409` when authorization changes, `403` when no matching RUN exists, `503` when unavailable). Secret plaintext and workload bearer tokens never enter the cached execution document. This is an internal endpoint, not operator secret read-back.

`AllocationRequest` has no allocation-level `Runtime`: each `TaskSpec` carries its resolved runtime and optional API access grant. `EnvOverrides` is `map[string]map[string]string` (task name → environment name → value), not one allocation-wide environment map. Deliver overrides only to their named task; sibling tasks must not inherit API endpoint, token, namespace, or CA injection. Restart policy remains allocation/task-group level. Leaders and agents must use the same release; see the [pre-v1 compatibility policy](../public/operations.md#upgrade-a-node).

The agent converges locally with one worker per allocation and independent namespace-plan workers. Cleanup precedes admission for an allocation; stalled runtime or credential work does not hold unrelated allocation workers. Starts persist their admission identity before background work. Interrupted admissions recover as failures unless matching task records establish execution; the same attempt is not silently replayed after restart. Heartbeats report failures and exact `(allocation ID, generation)` cleanup receipts. Neither a stopped task nor an omitted inventory entry proves resource cleanup. See [agent convergence](node-internals.md#agent-convergence) and [leader retry policy](control-plane.md#reconciliation).

Drain/resume state and namespace network plans converge from the projected document, not per-term delivery acknowledgements. `draining` and `drain_sequence`, like epoch and attempt, are outside execution identity. The agent applies sequenced drain state to established tasks as well as starts.

Local application of pulled network plans serializes admission and application through a caller-cancellable gate per namespace. Validation snapshots active attachments under the agent lock, but external network commands run without that broad lock, so unrelated start admission can proceed. An already admitted plan retains namespace exclusion until it returns; superseded document work is fenced before admission. Network command cancellation, periodic repair, and partial-application retries remain the network manager's responsibility.

Task attachment shares this gate and uses the latest accepted namespace topology, not the peer snapshot captured before a delayed image pull. Updates are retained even before the first attachment and after partial application failure, so retries cannot reinstall removed peers or routes. API-port access remains the starting task's execution grant, separate from topology; firewall repair reconstructs existing grants from attachment journals. Once the namespace has neither network attachments/intents nor unfinished starts, successful cleanup forgets its cached topology so a recreated namespace bootstraps from its new plan. Listener readiness gates node registration, heartbeats, and new start admission; stop and network cleanup remain available during DNS listener failures.

## Exec relay

Port 8127 remains a leader-initiated agent surface for exec, logs, and allocation metrics, not an outbound-only worker design. The client verifies the target node certificate, and the agent requires its locally known leader's node identity. Execution mutation is driven by node pull rather than leader start/stop/drain/network HTTP requests.

The [public exec WebSocket](../public/api.md#exec-streams) is authorized at the leader and relayed over the node-certificate mTLS agent API. Clients never connect directly to agents. The relay carries the control epoch: agents reject older epochs and end open streams when fenced by a newer one, while a leader ends its relays when its term ends.

The leader buffers one frame per direction; the agent queues at most four input frames. Output is unbuffered, applying backpressure to the process. A blocked frame times out after 30 minutes. Limits are 256 relays per leader, 64 sessions per node, and 8 per allocation; admission stays held until the process exits, including while failed kills are retried. Streams are ephemeral, not Raft state. An agent crash can leave an exec process running until it exits or its container stops; graceful shutdown kills it. Runtime process confinement is described in [node internals](node-internals.md#runtime-abstraction).
